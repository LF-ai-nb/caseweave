# 差异化与查重说明

本文用于说明 CaseWeave 的功能边界、原创关系和开源来源，避免被误判为近期常见的 Mooncakes 审查、报名材料审核或来源证明类项目。

## 一句话定位

CaseWeave 是一个确定性组合测试矩阵生成器：输入参数、取值、约束和风险提示，输出可复现、可导出、可在 CI 中验证的测试计划。

## 本项目明确不做什么

CaseWeave 不属于以下方向：

| 易混淆方向 | CaseWeave 为什么不是同类 |
| --- | --- |
| Mooncakes 包发布审查工具 | 不读取 mooncakes.io 包列表，不检查包是否能发布，不验证其他包的 README、许可证或元数据。 |
| README / License / 来源证明工具 | 不扫描仓库文件，不判断第三方来源，不生成开源来源证明报告。项目自身的依赖和许可证记录见 `NOTICE.md` 与 `LICENSE`。 |
| 报名材料审核或初审反馈工具 | 不读取报名表，不检查申报书合规性，不生成审核意见。 |
| 机器人策略、自动化策略或仓库治理工具 | 不处理 bot、policy、GitHub 事件、权限、Webhook 或自动评论。 |
| 随机性质测试、TAP 报告或代码覆盖率统计 | 不执行随机输入探索，不生成 TAP 输出，不统计代码行覆盖率。 |

## 与相邻测试工具的边界

CaseWeave 聚焦 constrained covering array，也就是“带约束的组合测试计划”：

- 生成目标是参数交互覆盖，而不是源码质量评分。
- 约束 DSL 用于排除不可行配置，而不是描述仓库治理规则。
- `audit` API 的含义限定为“覆盖验证”：检查一组测试用例是否覆盖目标参数交互。
- 修复计划只建议补哪些测试用例，不修改仓库、不调用外部服务、不执行真实环境测试。
- 风险排序只影响测试执行优先级，不判断项目是否能通过比赛初审或 Mooncakes 审核。

## 原创与关联关系声明

- 项目类型：原创 MoonBit 开源库。
- 公开仓库：`https://github.com/LF-ai-nb/caseweave`。
- Mooncakes 包名：`LF-ai-nb/caseweave`。
- 当前没有上游移植来源、关联闭源仓库、同名拆分仓库或未披露的基础项目。
- 当前没有第三方运行时依赖、外部素材、生成数据集或 vendored 源码。

如果未来版本参考、移植或扩展其他开源项目，必须在 README、`NOTICE.md` 和申报材料中写明原项目名称、链接、许可证、参考范围和改动范围。

## 自查结论

基于当前仓库内容，CaseWeave 与“包发布审查、README/许可证校验、来源证明、机器人策略、报名材料审核”类项目不存在核心功能重叠。它的维护价值来自测试工程本身：用更少、更可解释的测试用例覆盖更多配置交互，并把缺口修复和风险排序接入 CI。
