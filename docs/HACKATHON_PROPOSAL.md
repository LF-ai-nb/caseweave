## 项目背景与现有基础

现代软件经常面对配置组合爆炸：操作系统、浏览器、认证方式、区域、部署形态、功能开关等维度交叉后，完整笛卡尔积测试成本很高；但如果只靠人工挑选样例，又容易漏掉关键交互。CaseWeave 聚焦这一工程问题，使用 MoonBit 实现确定性的 constrained covering array 生成、覆盖审计和补测规划。

当前项目已经具备 MoonBit 包结构、README、设计文档、CI、测试、MIT License 和可运行示例。核心代码使用 MoonBit 实现，无第三方运行时依赖；有效 MoonBit 代码规模已超过 4,000 行。

## 本次开发内容

本次黑客松计划完成并完善以下能力：

1. 参数模型与输入校验：定义测试维度、取值、测试用例，并检查空值、重复参数、非法取值等问题。
2. 约束 DSL：支持 `==`、`!=`、`in`、`not in`、`and`、`or`、`not`、`=>`，用于排除现实中不可能出现的组合。
3. 确定性组合测试矩阵生成：支持 strength 1、2、3 及更高覆盖强度，在约束下生成可复现测试矩阵。
4. 覆盖审计与缺口解释：检查任意外部测试套件是否覆盖全部可行交互，并输出缺失交互。
5. 场景规格解析：用文本 spec 描述参数、约束、必须包含样例、排除样例和业务风险提示。
6. 风险排序与 CI 门禁：按业务风险对用例排序，并对覆盖完整性、用例预算、风险命中、规格质量做门禁。
7. 覆盖缺口修复：对已有测试套件生成补测建议，逐步补齐缺失交互，并提供补测门禁报告。
8. 文档、示例和测试：提供 API 文档、设计说明、验收说明、验证记录、可运行示例和核心路径测试。

## 技术路线

项目采用纯 MoonBit 实现。生成器先枚举满足约束的候选行，再收集目标 t-way 交互，通过确定性贪心策略选择每轮覆盖新增交互最多的候选用例，并进行冗余删除。约束解析器将字符串 DSL 转为 AST，在部分赋值阶段用三值逻辑提前剪枝。场景规格层负责把业务输入转为模型、约束、风险权重和门禁策略；修复计划复用同一套覆盖模型，对已有测试逐步建议最有价值的补测用例。

## 预期目标与验收方式

预期交付一个可复用、可发布、可长期维护的 MoonBit 测试工具库。验收时可通过以下命令复现：

```bash
moon fmt --check
moon check --deny-warn
moon build
moon test
moon run cmd/main
moon publish --dry-run
```

示例程序会展示从场景规格生成矩阵、输出风险排序、审计覆盖率，并从一条已有测试用例生成覆盖修复步骤。项目边界明确：CaseWeave 负责测试矩阵生成、覆盖审计、风险解释和补测计划，不负责执行浏览器、部署环境或外部系统测试。

## 差异化与维护价值

CaseWeave 不做随机性质测试、代码覆盖率统计、TAP 报告或提交材料自查，而是专注“带约束的确定性组合测试计划”。它适合接入 CI、发布前冒烟测试和兼容性测试流程，能帮助 MoonBit 生态项目以更少用例覆盖更多配置交互。后续可继续扩展文件输入、更多导出格式、场景模板、性能优化和更强的组合生成策略。
